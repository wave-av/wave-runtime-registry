## feat: @wave-av/wave-runtime-mcp — the agent-mountable MCP rendering of the runtime

### What

Adds `packages/wave-runtime-mcp` — a standalone MCP server (stdio transport, no external MCP SDK dependency) that exposes the WAVE Runtime to any MCP-capable agent (dsh, Claude Desktop, opencode, Cursor, etc.) through `runtime.wave.online`.

The MCP cell goes from "capabilities declared" to a real, mountable server. This is the agent-facing deliverable — agents mount it via stdio and immediately get three tools.

### Tools

- **`runtime_chat`** — Send a chat completion to the runtime. Takes `model`, `prompt`, optional `maxTokens`. Returns assistant content + token usage. Routes through `WaveRuntime.chat()`.
- **`runtime_models`** — List 5 available models with per-model `toolSupport` flags. `qwen3-coder:30b` is flagged `false` pending the tool-capable endpoint.
- **`runtime_usage`** — Return documented `wave_ai_tokens_inference_*` meter shape for a model. Best-effort, as meter reporting is runtime-dependent.

### Auth

Reads `WAVE_RUNTIME_API_KEY` (or `WAVE_GATEWAY_API_KEY` fallback) from environment only. API key is never accepted from tool call parameters.

### Mount Examples

**dsh (mcp-client patch):**
```json
{
  "mcpServers": {
    "wave-runtime": {
      "command": "wave-runtime-mcp",
      "env": { "WAVE_RUNTIME_API_KEY": "${WAVE_RUNTIME_API_KEY}" }
    }
  }
}
```

**Claude Desktop / opencode:**
```json
{
  "mcpServers": {
    "wave-runtime": {
      "command": "wave-runtime-mcp",
      "env": { "WAVE_RUNTIME_API_KEY": "your-key" }
    }
  }
}
```

### Implementation

- Pure JSON-RPC 2.0 over stdio (one JSON per line) — no `@modelcontextprotocol/sdk` dependency, keeps the dep surface minimal (only `@wave-av/runtime-sdk`).
- `runServer()` accepts a `Readable`/`Writable` pair, making it testable without process-level stdio mocking.
- `bin` entry point: `wave-runtime-mcp` → `dist/server.js`.
